# Handoff (updated 2026-10-09, end of the second session)

Kutumb is a standalone repo, no longer a GitHub fork: github.com/arjunravindran/kutumb. It began as a fork of f-tree by Ankit Srivastava and is used under f-tree's MIT licence, whose notice is kept in `LICENSE`. Per-feature history is in `NOTES.md`; the product spec is `docs/kutumb/SPEC.md`; the tree-sync design is `docs/kutumb/TREE-SYNC.md`.

**Branches:** the working branch is `kutumb`; on the remote it is `main`. Push with `git push origin kutumb:main` (a plain `git push` fails because the names differ). A separate local `main` holds the original f-tree history; ignore it.

## What exists

- **The app** (Android): family tree, chart and compact views, kinship names (English, Hindi), nearby sharing, family book PDF, birthdays, trust/pairing, facts game, messages, sync over Nostr relays (opt-in; once on, it uses nos.lol unless the person chose others under Advanced), Circles.
- **The website** is live at https://kutumb.arjun.contact (Cloudflare Pages: project `kutumb`, production branch `main`, no build command, output directory `site`; every push to `main` redeploys). Privacy policy: https://kutumb.arjun.contact/privacy/. Fonts (Literata, JetBrains Mono, OFL) are served from `site/fonts/`, not Google.
- **The web viewer** (`site/playground/`) is an installable PWA (manifest, icons, service worker). It is **view-only**: it never imports the `.ftree` writer. It keeps the last tree you opened in the browser's own storage (IndexedDB) so an installed copy reopens on it; **Close** or unticking "Keep my tree on this device" deletes it. `remember.js` and its tests cover this.
- **The desktop app** (`desktop/`, Electron) loads the same viewer code.
- **Tree sync** (new): see below. Reachable from **Settings > Your trees > Sharing** on the open tree.
- **Made for readers over sixty** (this session): the bottom bar has three places, **Tree, People, More**; More is a plain list of big rows leading to Network, Facts and Settings (Facts hidden in a Circle; `ui/more/MoreScreen.kt`). Body text is larger (16sp, was 14; the smallest labels 13 to 14sp) in `ui/theme/Type.kt`. The empty first screen says what Kutumb is in one line, gives three numbered steps and one big **Add myself** button, and scrolls so a large system font cannot push the button away. Sync defaults to `wss://nos.lol` once switched on (still off by default), and the relay editor sits under **Advanced: choose the servers**. The sync wording and the privacy page were rewritten in plain words.
- **First-run welcome (2026-10-10):** a full-screen page, shown once, to a new install with an empty tree: three short promises (private by default, the right name for every relative, share with relatives you meet) and one **Get started** button (`ui/welcome/`). Somebody who updated an older version, and so already has people, is marked as welcomed without seeing it. The decision is a pure function (`WelcomePolicy`, 5 JVM tests). **Held back in instrumented runs**, because those start from empty installs all the time: a test that wants it stores `false` (`WelcomePreferences.showAgain()`), as `WelcomeFlowTest` does. To see it by hand: `run-as contact.arjun.kutumb.debug` and write `shared_prefs/welcome.xml` with `<boolean name="seen" value="false" />`, then launch.
- **Add people from my contacts (2026-10-10, emulator only, not yet tried on a phone with real contacts):** the way to fill an empty tree quickly. A second button under **Add myself** on an empty Tree or People screen, and a row on **Settings > Save and import**, open a full-screen page (`ui/phonebook/ContactsImportDialog.kt`; not a navigation destination). **READ_CONTACTS** is asked for only when the reader taps **Allow contacts**, and only names and birthdays are read (`phonebook/`); phone numbers, addresses and emails never are. On an **empty tree** the reader types their own name and ticks contacts, choosing for each how they are related (mother, father, sister, brother, husband or wife, daughter, son, or no connection), and the tree is built in one go, parents first so a sister is attached to them. On a tree **with people** the ones ticked are added without connections and anybody already there (same name, any case or spacing) is left out. In a **circle** there are no relations to choose. Pure logic (`Phonebook`, `ContactsImport`) has 20 JVM tests; `ContactsImporterTest` (4, real database) and `ContactsImportFlowTest` (2, with a fake address book) cover the rest; the real address-book query is thin and was **not** tested against real contacts. The privacy page and the in-app permissions text name contacts. **Play Data safety:** declare that contacts are read on the device and not collected or shared. Not built: matching a contact to somebody already in the tree by anything but name, contact photographs, reading a relationship label from the contact itself (Android keeps those on the *other* person's card, so they are rarely filled in), and a "select all".

## Tree sync: where it stands

Design: `docs/kutumb/TREE-SYNC.md` (read it before touching this). Built and tested:

1. **Pure core** (`kutumb-core/.../kutumb/treesync/`): hybrid logical clock, seven operations, last-writer-wins registers per person / field / relationship, a *view* that hides parent loops and edges to unknown people without dropping them, an edit recorder, a projection (view to database steps), a reconciler (database to operations), and a wire codec. Convergence is tested with shuffled, duplicated random streams and a three-phone simulation with skewed clocks.
2. **Room** (schema v4, `MIGRATION_3_4`, create-only): `tree_sync_meta` (present only if shared), `tree_sync_ops` (append-only log), `tree_sync_members`. `TreeSyncCoordinator` rebuilds the replica from the log, records changes (a Room invalidation observer, so imports and seeds are covered), and applies received operations in one transaction. v4 was never released, so the members table was added in place.
3. **Wire**: `TreeSyncHandler` accepts edits only from contacts **paired in person**, for **this** shared tree, who are **members**; `TreeSyncPublisher` sends in batches of 100 through the existing outbox; `shareTreeWith` adds a member and sends the whole history. `AppContainer` starts it only when a tree is shared.
4. **Sharing screen** (`ui/settings/TreeSharingDialog.kt`, rules in `kutumb/treesync/TreeSharing.kt`): a Sharing button on the open tree's row in Settings > Your trees. It switches sharing on, lists contacts paired in person with a switch each (on = member and is sent the tree), shows "N changes waiting" and a note when sync is off. Only the open tree can be managed (sharing lives in its own database). Tested on the JVM and on the emulator against a throwaway tree.

**Pushed 2026-10-09:** the cleaned history was force-pushed to `main` (`e7f3102` to `4237ddb`), the repo is public, and three later commits followed: the Settings fold-away row, the plain-words permissions text, and plain words for export, import and sharing. Nothing local is unpushed except what is committed after `e1802ca`.

Not built: **phase 4's nearby snapshot** for big trees (joining sends the whole history over the relays, which is slow but correct), catch-up for a phone that has been away, **phase 5** (photos) and the review inbox screen (`TreeSyncCoordinator.inbox()` exists). The join step is built; see below.

## Gotchas

- **Memory.** The machine has 23.4 GB. The emulator holds about 4 GB (it is started with `-memory 3072` and uses more), the Gradle and Kotlin daemons about 3.3 GB, Android Studio about 1.7 GB. Windows killed a full run once for low memory. Before a full instrumented run: `./gradlew.bat --stop`, quit Notion and Spotify, and keep Android Studio closed. A 14 to 21 minute run is realistic; a 32 GB or rented Linux machine (Google Cloud with nested virtualization, or a Hetzner dedicated server) was discussed but nothing was rented. CI already has an emulator job.
- **Do not leave test data in the emulator's debug app.** Seeding or clicking around in `contact.arjun.kutumb.debug` changes what the instrumented tests see (a leftover seeded tree made `TreeSharingFlowTest` fail). Run `adb -s emulator-5554 shell pm clear contact.arjun.kutumb.debug` first.
- **Tab switching must not save or restore a stack** (`switchTo` in `FTreeApp.kt`): More holds screens of its own, and a restored stack put the reader back on Settings when they tapped Tree. Instrumented tests reach Network, Facts and Settings by tapping `NavMoreTag` then `MoreNetworkTag`, `MoreFactsTag` or `MoreSettingsTag`.
- **Line endings are mixed.** `FTreeApp.kt`, `SyncPreferences.kt`, `SyncPreferencesTest.kt` and a few others are CRLF; most files are LF. `grep -c $'\r'` gave wrong answers in this shell, so check with Python (`open(p,'rb').read().count(b'\r\n')`) before a scripted edit, and match the file.
- **Scripted edits through bash heredocs break on quotes and `\n`.** Write the script with the Write tool, then run it.
- `adb`, `emulator` and `python` are not on PowerShell's path here; use Git Bash, and `C:/Users/arjun/AppData/Local/Android/Sdk/platform-tools/adb.exe`. **Two real phones are attached**: always pass `-s emulator-5554` or set `ANDROID_SERIAL`.

- **Real-phone testing over adb:** the Pixel's screen times out after 30 s and then screenshots come back black, so send `KEYCODE_WAKEUP` before each step. Never press Back repeatedly: it leaves the app and lands in whatever was open before. The app does not log pairing steps; the stored state is the evidence (`run-as contact.arjun.kutumb.debug cat databases/f-tree.db` plus the `-wal` and `-shm` files, read with sqlite3).
- **What the first real run showed:** (a) a message from a phone that has not yet been added as a member is dropped by design, so add each other on **both** phones before editing; (b) after adding a member the Sharing screen keeps saying "N changes waiting" until the next pass sends the backlog, because sending a new member the whole history does not mark operations as sent; (c) when the relay is slow to reach (the Pixel measured 250 to 1100 ms to nos.lol while the Samsung measured about 230 ms) the websocket connect fails and is retried once a minute, and it took about nine minutes for a change to arrive; (d) `connect failed` is logged without the underlying error.
- **Never run `connectedDebugAndroidTest` with a phone attached unless `ANDROID_SERIAL` names the emulator**, e.g. `ANDROID_SERIAL=emulator-5554 ./gradlew connectedDebugAndroidTest`. Start it with `emulator -avd Medium_Phone_API_35 -no-snapshot -no-audio -memory 3072`.
- Gradle can report success when the device runner failed: read the result XML under `app/build/outputs/androidTest-results/connected/debug/`. `gradlew.bat` splits arguments at commas, so run one test class at a time.
- On Windows, **do not cut a Gradle run short with `Select-Object -First N`** (it can stop Gradle mid-run and leave odd results).
- Some JVM tests run the JavaScript composer and are skipped without Node; CI sets `FTREE_REQUIRE_NODE=1`. On Windows a few of them (and `desktop/atomic.test.js`, `tools/check_writer.mjs`) fail for path or file-replace reasons that do not occur on Linux.
- To regenerate the book goldens after an intended change: `UPDATE_GOLDEN=1 node --test book.test.mjs` in `site/book`. The QR is `SITE_URL` re-encoded with `desktop/renderer/vendor/qr.js` (error correction M), as `qr.test` checks.
- `.ftree`, nearby wire labels (`f-tree/nearby/1/...`), database and identity file names, and the package namespace `com.vibethroughcode.ftree` keep the f-tree name on purpose: renaming them would break data and pairing. The installed debug app of an older identity is `com.vibethroughcode.ftree.debug`; the new one is `contact.arjun.kutumb.debug` and starts empty.
- A broad `sed` over the repo also rewrites ignored caches such as `.gradle/`; exclude `.gradle`, `build`, `node_modules` and `.git`.
- Tooling: there is no `gh` CLI; the GitHub token available to the assistant cannot create repositories or read Actions logs. Read a failing run on the Actions page and paste the log.
- **A failed compile leaves the last run's result files in place.** `app/build/outputs/androidTest-results/connected/debug/TEST-*.xml` from the run before is still there, so a grep of it after a build that did not compile reports the old numbers. **Delete `app/build/outputs/androidTest-results` before a run you mean to trust**, and check that the file exists afterwards. (This session reported four passing runs of one class that way, from a file that was stale; it was caught and the runs were repeated.)
- **Compose state written from a database thread may not be picked up.** After a Room call a coroutine can continue on one of Room's threads; the Sharing dialog assigned its state there and sometimes stayed on "One moment…" for ever, so `TreeSharingFlowTest` failed anywhere from 0 to 3 of its 3 tests per run (found with logging that showed the load finished in milliseconds while the screen did not change). It now writes its state inside `withContext(Dispatchers.Main)`; 15 of 15 runs passed after. **Other screens that assign state after a database call may have the same weakness**; do the same if one shows a stuck spinner.
- **Emulator and tooling notes (2026-10-10).** Keep it awake (`adb shell svc power stayon true`) and disable the Google search app (`adb shell pm disable-user --user 0 com.google.android.googlequicksearchbox`), which sometimes takes the foreground. After a cold boot start it with `emulator.exe ... ` as a background task, not with `nohup` in a subshell. Connected tests uninstall the app afterwards, so `run-as` fails until you `installDebug` again. Git Bash rewrites `/data/...` paths: set `MSYS_NO_PATHCONV=1` for `adb push` and `run-as`. Node is `C:\Program Files\nodejs\node.exe` and is **not on any PATH here**; the desktop package test also needs `npm ci` in `desktop/` (it reads `@electron/asar`).
- **Joining fills a nearly empty tree in place (2026-10-10).** Two first-use stories: the first one in uses **Add people from my contacts**; somebody invited in the room installs, adds themselves and the relative (pairing needs that person in the tree), pairs, and on saying yes to the invitation gets the inviter's tree *in the tree they already have*. `JoinPlan.fillsInPlace(shared, people, relationships)` (JVM-tested) decides: not shared, at most 2 people and 1 relationship, and the tree must be the open one that heard the invitation (`FTreeApplication.fillOpenTree`). Then `clearAllTables()`, `prepareJoinedTree`, and `reopenActive()` rebuild the wiring; the inviter sends everything, this phone's own person included, under the inviter's ids. Anything bigger, shared, or not the open tree still gets a new tree beside it, as before. Contacts imported afterwards, inside the shared tree, sync back to the inviter. The welcome has a second button, **Someone invited me**, that lists the steps. `TreeSyncCoordinatorTest.aNewcomerWithAlmostNothingIsFilledInPlace` covers the data side; the in-place path through the real app (relays) has **not** been tried on phones. Still not built: merging two real trees (`person.merge`), retrying a lost `tree-join`, offering the larger tree.
- **The two real phones (2026-10-10).** Pixel 7 `34011FDH2000VL` was given the **full tree**: the old-id debug app was uninstalled, `contact.arjun.kutumb.debug` installed, and `mode family` seeded (13 people, 15 parent edges, 4 marriages, **not shared**). The Samsung S22+ `RFCT32HLRFZ` was **not attached** that evening (unplugged, or USB debugging not authorised) so it was not touched; it is meant to be the **empty, new-user** phone and still has the old-id app. Both start with family sync **off** (it is opt-in) and with no pairing, because the new app id is a new app. For the first-use story: on the new phone tick through the welcome, **Add myself** (or **Add people from my contacts**), set who you are under Network, pair in person, switch **Family sync** on on both, then on the full phone **Settings > Your trees > Sharing** and switch the new phone on; the new phone gets a row on **More** and a dot on the tab. **Known wrinkle:** joining always makes a *new* tree beside the existing one (the "fill an empty tree" rule is not built), so a new phone that imported contacts first ends with two trees; adding contacts *after* joining, inside the shared tree, avoids that and skips anybody already in it.

## Decisions (don't re-ask)

Google Play distribution (F-Droid is not a target). Android to Android only for the app; **iPad gets the view-only PWA, with no native iOS app for now** (revisit after the PWA has been used). Sync is opt-in (off by default) with `wss://nos.lol` as the default relay once on (decided 2026-10-09 so older users need not pick one; relay choice is under Advanced). The bottom bar has three places: Tree, People, More (Network, Facts, Settings live under More; decided 2026-10-09 for readers over sixty). No recovery path for someone with no relative nearby and no key backup. One database per tree; kinds Family and Circle; one identity key per phone. A change made while sync is off is not queued. Tree sync: everyone paired in person and added may edit; a delete beats a concurrent edit but is undoable; a second phone starts from a snapshot with the same ids; photos are not in v1. Kutumb is a separate app from f-tree, with f-tree and its MIT licence acknowledged. Ship it as 1.0.0 (`versionName` 1.0.0, `versionCode` 34 already). **Joining a shared tree (2026-10-09):** it never merges silently. If the joiner's own tree is empty or holds only themselves, joining fills it; otherwise it makes a new tree beside it. For someone with a larger tree, a later step offers to run that tree through the existing import review into the shared one (matches take the shared ids), so no `person.merge` is needed. Defaults taken: the relay path alone for v1, and the joiner is asked before a tree is created. Full text: `docs/kutumb/JOIN-SHARED-TREE.md`.
